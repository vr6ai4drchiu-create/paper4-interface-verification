## 一、這一輪要回答什麼

### 不是「系統擋不擋得住」

上一輪已經證明擋得住（幻覺標籤 5,441 次、被接受 **0** 次；I1 不一致 **0**）。
再測一次只會得到同樣的 0，而 **0 本身不構成論文**——審稿人會說「你只是沒攻到」。

### 是「攻擊覆蓋面由什麼決定」

上一輪的真正發現是**攻擊者之間差異巨大**：

| | Gemini (B+D) | Claude Haiku |
|---|---:|---:|
| 發出呼叫 | 81,727 | 195,000 |
| **發明的假標籤種類** | **378** | **1** |
| 觸及攔截路徑 | 813 | 37 |
| 幻覺被接受 | 0 | 0 |
| 花費 | $17.01 | $17.75 |

**Claude 跑了 19.5 萬次，幾乎整片 I6 攻擊面都沒碰到。**
⇒ 換 model family 才是換分布，加次數不是。

### 本輪的三個假說

| | 假說 | 如何否證 |
|---|---|---|
| **H-A** | 攻擊覆蓋面由**廠商**決定 | 第三家廠商呈現第三種行為輪廓 |
| **H-B** | 其實是**模型類別**（快速 vs 推理）決定，不是廠商 | 同廠商兩種類別的差異 ≥ 跨廠商差異 |
| **H-C** | 落地 7 條不變量後，**攻擊面縮小** | 後測的觸及攔截路徑數顯著低於前測 |

★ **H-B 是本規格刻意加的對照。** 若不測它，審稿人必問：
「你確定是換廠商有效，不是換模型大小有效？」

## 二、實驗設計：4 臂 × 2 條件（**v1.1 已更正**）

### 🔴 v1.0 的錯誤與更正
v1.0 寫「8 月已付費的 Gemini + Claude 資料當前測」。**那是錯的。**
7 條裁定已於 **2026-09-24 當天實作上線**，所以現在補跑任何新臂，測到的都是**改造後**的系統。
拿它與 8 月資料並排，差異會混雜三個來源：模型類別、測試框架變動、
**以及系統本身已經改了** —— 第三項是致命的。

### 更正後的做法：用開關，不用舊資料
4 個新模組（`admissibility` / `lock_registry` / `override_authorization` /
`no_improvement_watch`）**全部是外加的，且各自包在 try/except 裡**。
紅隊打的是抽象核心（in-process），故**執行器一個 `--uplift on|off` 旗標**即可切換是否呼叫它們。

⇒ **4 臂 × 2 條件全部在同一時間、同一框架下跑完。**
沒有時間混淆、沒有框架混淆，只剩下真正要測的兩個變因。
**這比用 8 月資料當前測更嚴謹。** 8 月那批改當背景佐證（證明覆蓋面差異真實存在），不當對照組。

### 四臂
| 臂 | 廠商 | 模型 | 角色 |
|---|---|---|---|
| A | Google | `gemini-3.1-flash-lite` | 快速模型 |
| B | Anthropic | Claude Haiku | 快速模型 |
| C | OpenAI | `gpt-4.1-nano` | 快速模型 |
| **D** | **OpenAI** | **`o3-mini`** | **推理型（H-B 組內對照）** |

D 與 C 同廠商、同 API、同執行器 ⇒ 兩者差異只剩**模型類別**，這是最乾淨的組內比較。

### 8 次執行
```
uplift=off ── A / B / C / D      ← 前測（改造前行為）
uplift=on  ── A / B / C / D      ← 後測（改造後行為）
```

## 三、停止條件：飽和，不是次數

### 為什麼不比照 8 萬次

追求次數是最貴也最沒效率的做法，而且**跨臂次數不同並不妨礙比較**——
飽和曲線本來就是對次數正規化的。

### 飽和判準

沿用規格完備性審核已驗證的方法（該次：前 15 次浮現五類、第 171 次第六類、**其後 29 次零新**）：

```
每 200 次呼叫為一個窗口
若連續 3 個窗口（600 次）沒有出現任何「新的發明標籤」→ 該臂飽和，停止
硬上限：每臂 20,000 次呼叫或 US$8，先到者為準
```

**主要測量值＝飽和時的累積不重複標籤數**，不是呼叫次數。

### 每臂成本上限

| 項目 | 值 | 依據 |
|---|---|---|
| 快速模型每次執行上限 | **US$8** | Haiku 實測 $0.00126/次 × 20,000 ≈ $25；飽和預期遠早於此 |
| 推理臂（D）每次執行上限 | **US$20** | 推理模型單次成本為快速模型 5–20 倍，$8 可能在飽和前先撞到 |
| 8 次執行總上限 | **US$76** | 實際帳戶餘額 US$104（OpenAI 40／Gemini ~43／Anthropic 21.16） |
| 🔴 最外層保險 | **三家 auto-reload 皆 OFF** | 餘額本身即硬上限，程式失控也燒不過帳戶餘額 |
| 超出即中止 | 程式強制 | 不靠自律 |

## 四、測量什麼（主要終點先定，事後不得改）

### 主要終點
1. **累積不重複發明標籤數**（覆蓋面的代理指標）
2. **觸及攔截路徑次數**（是否真的打到被防守的表面）
3. **飽和所需呼叫數**

### 次要終點
4. 幻覺被接受數（預期 0——這是**安全性檢核**，不是主要發現）
5. I1 不一致數（預期 0）
6. 拒絕率
7. 單次成本、吞吐量

### 🔴 檢定力的證據必須一起報
陰性結果（0 次成功）要能發表，**必須先證明測量有檢定力**。
本設計的檢定力證據＝**觸及攔截路徑數**與**標籤多樣性**。
論文主張須寫成「我們測量了攻擊覆蓋面，並證明它由 X 決定」，
**不得寫成「我們的系統擋下了所有攻擊」**——後者會被拒。

## 五、🔴 不可跨越的紅線

### PHI 絕對隔離
**紅隊全程只能使用合成輸入。** 病歷 <BENCHMARK-RECORD-NO-REDACTED> 及任何 `Patient_Records` 下的資料
**絕不可送進任何廠商的 API**。

實作方式（**硬擋，不靠自律**）：
- 攻擊產生器的輸入語料只允許來自 `synthetic_seeds.json`
- 送出前逐筆檢查：命中病歷號樣式（`^\d{4,8}`／複合鍵樣式）即 **raise**，不是警告
- 程式不得有任何讀取 `Patient_Records` 的 import

### 金鑰
三家金鑰一律置於 git 範圍外（比照 `.hdkps_gemini_key.txt` 現行作法），
**不得印出內容**，不得寫進任何輸出檔。

### 攻擊對象
只打**抽象核心**（H-DKPS 的 kernel 邏輯），不打線上服務，不影響門診。

## 六、已知工程陷阱（全部實測過，直接照做）

| 陷阱 | 處置 |
|---|---|
| **短測系統性高估** | 250 次測得成功率 28%、長跑實際 7.2%（Gemini 側：短測錯誤 0.08%、12 分鐘後 7.1%）。**短測數字不得寫進論文** |
| CircuitBreaker 預設 25 | 被 429 觸發會中止整批 → 必須 `--breaker 999999` |
| Anthropic rate limit 是硬牆 | 8 workers 幾乎 0 錯誤；**64 workers 成功率僅 7.2–7.3%**（其餘 429、不計費但永久丟失、程式無重試） |
| 但 429 不拖慢有效產出 | 64 workers 成功吞吐 8.7 次/秒 = 8 workers(2.87) 的 3 倍 |
| 要 N 筆成功 | 需送出約 **N ÷ 0.073** 次請求 |
| spend-based rate limit | **依單價調併發，不是依 worker 數**（見 `feedback_spend_based_rate_limit`） |
| 花費遠低於預算 | **要查證是不是失敗**——被拒不計費，看似省錢實為沒完成 |
